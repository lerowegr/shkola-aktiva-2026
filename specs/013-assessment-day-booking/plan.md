# План

Nuxt/Vue/Nitro/Prisma/PostgreSQL остаются прежними. Использовать AssessmentSession как временной слот: новый слой дней/факультетов — группировка чтения, не дублирование слотов и лимитов.

1. Приглашению добавить invitedDay (московская дата), invitedFaculty и reserveOffered. Старые даты/факультеты заполнить из текущих записей без изменения sessionId/answer. AssessmentGroup.faculty nullable сохраняет исторические общие группы.
2. Общие чистые правила дня и двухчасовой границы в rules.ts. Вместимость в capacity.ts — GOING и совместимость прежнего RESERVE без очереди. Все операции под существующим замком сезона.
3. Рассылка создаёт приглашение на день без ограничения capacity; snapshots слотов опубликованы, но новые времена не выбираются автоматически. Автоприглашения только в дни уже начатой рассылки. Уведомление адресовано индивидуальному факультету, предлагает времена его дня; очередь резерва отдельно получает предложение выбрать из времён резерва, без брони.
4. candidate.ts читает отдельно обычные и резервные слоты по faculty/date, возвращает full/closed/current. Выбор/отказ/резерв проверяет snapshot времени, атомарно меняет запись и снимает старую подгруппу; начатые оценки остаются, пустые заготовки синхронизируются.
5. Обзор организатора группируется по шести дням и факультетам; кнопка приглашения на день/факультет передаёт faculty. Форма времени поддерживает несколько резервных слотов одного дня и факультеты резерва. Форма подгрупп и переносы ограничены faculty.
6. Полный check, браузер 375px, сверка требований, коммит, пуш и подтверждение миграции/здоровья прода. Боевые персональные данные не используются для тестов.

Конституция I–VI: все записи через защищённые defineAction; аудит организатора; группировка факультетов не ограничивает права просмотра; уведомления notify; никаких утечек оценок; тесты sha_test. Существующие административные исключения лимита сохраняются с предупреждением, обычная запись строго лимитирована.
