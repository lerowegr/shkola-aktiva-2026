# Research: Доработки лендинга по отзыву

Решения для неясных мест плана. Формат: решение → почему → что отвергли.

## R1. Обработка фото на сервере

- **Решение**: `sharp` (0.35.x). При загрузке фото декодируется, поворачивается по EXIF,
  метаданные (в том числе GPS) выбрасываются, сохраняются webp-варианты шириной 480, 960 и
  1600 px и «мастер» до 2400 px для будущей перегенерации.
- **Почему**: декодирование заодно проверяет, что файл — действительно изображение; один
  результат на всех устройствах; EXIF с координатами съёмки не уходит на публичный сайт.
  Готовые сборки `sharp` есть для macOS arm64 и Linux x64/arm64 — подходит и для разработки,
  и для будущего VPS в Docker.
- **Отвергли**: уменьшение в браузере организатора (canvas) — нет общего контроля качества,
  HEIC не открывается вне Safari, сервер всё равно должен проверять файл; хранить исходники
  как есть — 3–5 МБ на фото с телефона уничтожат скорость главной.
- **HEIC**: готовые сборки `sharp` HEIC не читают (патенты). Сообщение при загрузке:
  «Фото в формате HEIC — сохраните его как JPEG (на iPhone: Настройки → Камера → Форматы →
  Наиболее совместимый)».

## R2. Хранение и раздача фото

- **Решение**: файлы в `UPLOADS_DIR/site/<key>-<ширина>.webp`, запись `SiteImage` в базе.
  Раздаёт публичный маршрут `/media/site/<id>/<ширина>.webp` с
  `Cache-Control: public, max-age=31536000, immutable` — содержимое по id никогда не меняется.
- **Почему**: как у домашних заданий — файлы вне `public/` (конституция IV), но фото сайта
  публичны по смыслу, поэтому без проверки прав. Неизменяемость даёт вечный кеш в браузере и
  на будущем прокси.
- **Отвергли**: класть в `public/` — в прод-сборке папка статическая, во время работы туда
  не пишут; base64 в JSON — раздувает тексты сайта и страницу.

## R3. Как тексты ссылаются на фото

- **Решение**: в `SiteContent` фото — ссылки `{ id, alt }`: alt (что на фото) живёт рядом с
  местом использования. Сервер при сохранении проверяет, что все id существуют.
- **Почему**: одно фото может понадобиться в разных разделах с разными подписями; схема
  остаётся одним документом, как сейчас.
- **Отвергли**: alt в `SiteImage` — подпись зависит от контекста; отдельные таблицы людей и
  фото места — ломает принятую модель «тексты сайта — один документ».

## R4. Уборка неиспользуемых фото

- **Решение**: при сохранении текстов удаляются фото, на которые больше нет ссылок и которые
  загружены больше часа назад (файлы и записи). Час — запас на «загрузил, но ещё не сохранил».
- **Почему**: без уборки диск копит удалённые и заменённые фото.
- **Отвергли**: удалять сразу при удалении из формы — пользователь мог передумать до
  сохранения; периодическую задачу — лишняя движущаяся часть.

## R5. Перебивка «сборка логотипа»

- **Решение**: отдельная секция, закреплённая на экране на время прокрутки (GSAP
  ScrollTrigger `pin`, ~150% высоты экрана, `scrub`). Своя сцена из модуля
  `voxel-scene` в режиме «сборки»: объекты из разлёта по прогрессу летят к позициям вокруг
  центра, где у стикера стоят те же объекты, и тают; поверх из 0.6 в 1 вырастает стикер.
  Сцена создаётся, только когда секция в пределах экрана от видимой области, и не рисует
  кадры вне видимости.
- **Почему**: связывает первый экран с серединой; переиспользует готовые 3D-объекты.
- **Без WebGL / «уменьшить движение»**: без закрепления — неподвижный стикер с картинками
  объектов вокруг.
- **Отвергли**: видеоролик — тяжелее и не реагирует на прокрутку; второй экземпляр
  героя на одном холсте — героя тогда нельзя останавливать вне видимости.

## R6. Маскоты со следящими глазами

- **Решение**: глаза нарисованы на картинках, поэтому поверх каждого глаза кладём белый овал
  с чёрным зрачком, который сдвигается в сторону указателя. Координаты глаз найдены
  автоматически по картинкам (белые овалы с тёмным зрачком) и проверены наложением — для
  13 из 15 маскотов; в финал идут `green`, `purple`, `blue-a`, `yellow-b`.
- Указатель — общий слушатель `pointermove` с обновлением раз в кадр; на телефоне — последнее
  касание; без указателя глаза смотрят на кнопку. Наведение или фокус на «Подать заявку» —
  маскоты подпрыгивают.
- **Отвергли**: перерисовать маскотов в SVG — нужны исходники брендбука; 3D-маскоты — тяжело
  и не похоже на мелок.

## R7. Лента людей

- **Решение**: тёмная секция (`bg-ink`, фактура плитки бренда), бесконечная лента карточек
  через CSS-анимацию дорожки (дубль содержимого для бесшовности), пауза при наведении, фокусе
  внутри и касании. Карточка — фото-слайдер: свайп, стрелки, точки-счётчик. Фото по мере
  приближения (`loading="lazy"`, `srcset`).
- **«Уменьшить движение»**: ленты нет — горизонтальный ряд с прокруткой и привязкой к
  карточкам.
- **Почему**: «элементов много» — лента не растягивает страницу. Единственная текстовая
  бегущая строка остаётся одна (правило дизайна): здесь лента карточек.
- **Отвергли**: сетка — при 40 людях страница становится длиннее всех остальных разделов.

## R8. Карточки программы

- **Решение**: CSS 3D-переворот (`rotateY(180deg)`, `backface-visibility: hidden`),
  лицевая сторона парит (покачивание по CSS-анимации со сдвигом фаз). Карточка — кнопка с
  `aria-pressed`; переворот по клику, касанию, Enter и пробелу. Без описания —
  не кнопка и не переворачивается.
- **Отвергли**: карусель-«3D-слайдер» — по ответу владельца речь о перевороте карточки.

## R9. Таймлайн истории

- **Решение**: на главной — 3 события с самыми поздними годами и кнопка «Вся история»;
  полный таймлайн — нативный `<dialog>` на весь экран (фокус внутри, Esc закрывает,
  прокрутка страницы под ним не меняется), события по годам с липкой лентой годов для
  быстрого перехода.
- **Отвергли**: отдельная страница — теряется место на главной; раскрытие на месте —
  страница прыгает на десятки экранов.

## R10. Анимации вопросов

- **Решение**: нативный `<details>` (доступность), высота ответа анимируется через Web
  Animations API при открытии и закрытии; вопросы появляются при прокрутке по очереди
  (`motion()` + GSAP).
- **Отвергли**: CSS `::details-content` + `interpolate-size` — пока не во всех браузерах.

## R11. Значки Telegram и ВКонтакте

- **Решение**: пути значков из `simple-icons` (CC0), импорт `siTelegram` и `siVk` —
  в сборку попадают только они.
- **Отвергли**: рисовать значки вручную (правило дизайна); Lucide — брендовых значков нет.

## R12. Плашка «Подать заявку»

- **Решение**: один компонент для первого экрана и финала — «наклейка» бренда: яркий фон,
  толстая чёрная обводка, жёсткая тень со сдвигом, лёгкий наклон. Внутри: живая точка,
  строка состояния, «осталось N дней» по Москве (из даты закрытия), кнопка.
- **Почему**: контраст и узнаваемость, одна формулировка на одно намерение.

## R13. Выделение текста при игре с 3D

- **Решение**: на первом экране `user-select: none` и `-webkit-touch-callout: none` для
  всего, кроме подзаголовка и плашки с состоянием (у них `select-text`);
  `-webkit-tap-highlight-color: transparent` на холсте.
- **Отвергли**: `preventDefault` на `pointerdown` — ломает фокус и прокрутку касанием.
