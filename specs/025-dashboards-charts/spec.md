# Дашборды графиками

## Зачем
Дашборды читаются как таблицы; руководителю нужны графики: кто когда проходил этапы, статистика по факультетам, корпусам и мастерам.

## Истории
- US1 «Кто когда проходил»: по московским дням — отправили анкету, пришли на ЦО, собеседования, приняты. Переключатель «за день / накопительно». Фильтры: факультет, курс, период (с–по), корпус.
- US2 «Радуга факультетов»: все 8 факультетов на одном графике — сколько отправили анкету, пришли на ЦО, собеседовались, приняты. Срез по корпусу — отдельный график (ЦО и собеседования по корпусам).
- US3 «Мастера»: фильтр по мастеру; его собеседования по дням (слоты и записи); согласованность — расходящиеся столбики «строже/мягче»; остальное по мастерам фильтруется точечно, воронку мастер не фильтрует.
- US4 Существующие таблицы становятся графиками: свободные места — составные столбики «записано/свободно»; не записавшиеся — по факультетам; исходы по факультетам — составные столбики; средние по этапам, вовлечённость — столбики. Разрывы и согласованность дублируются графиками, таблицы остаются.
- US5 Период «с…по» действует на отчёты по дням (прохождение, уведомления).

## Правила
- Цвета серий ≤5 на графике; у факультетов — 8 узнаваемых цветов бренда-палитры.
- Под каждым графиком — переключатель «таблица» (доступность).
- Время по Москве; новые агрегаты только из существующих таблиц.
- Права прежние: dashboards.view на чтение и CSV.

## Критерии приёмки
- Все перечисленные графики открываются, фильтры меняют числа, таблица каждого графика совпадает с ним.
- Тесты агрегатов проходят; npm run check зелёный.
