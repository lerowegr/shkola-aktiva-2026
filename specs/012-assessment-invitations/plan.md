# Implementation Plan: Центр оценки — приглашения на сборы, подгруппы, комментарии

## Дополнение: очередь резервного дня

RQ-001–RQ-006: `AssessmentInvite.reserveQueued Boolean @default(false)` отделяет очередь от прежних назначенных RESERVE. Миграция сохраняет существующие приглашения. Новый ответ RESERVE ставит флаг; `dayOf` возвращает null для очереди даже после создания сбора. Очередь не занимает места резервного слота, но сохраняет исходное приглашение. `answeredAt` задаёт FIFO; повтор не меняет его.

`inviteReserveQueue` в `lib/assessment/sessions.ts` под общим замком сезона выбирает активные SUBMITTED анкеты FIFO, резервный будущий сбор, проверяет место/снимок и вместимость. Снимает флаг только с выбранных; после транзакции шлёт срочное `notify` с уникальным ключом. Новый POST `reserve-invite` защищён `applications.assign` и аудитом. Чтение очереди — в `loadOverview`; только организаторам и имеющим view_all, не обычным экспертам. UI кандидата показывает ожидание и кнопку без обязательной даты; обзор — отдельный список и запуск рассылки. Существующие назначения и правила подгрупп сохраняются.

Конституция I–VI: права и аудит на сервере, доставка через notify, оценки не меняются, русские тексты/Москва/375px, тесты на sha_test. Проверки: очередь без сбора, создание без рассылки, FIFO, лимит 50+остаток, гонки, отмена, сохранение прежних назначений, ручная мобильная проверка.

## Summary

Новая сущность «Сбор ЦО» (дата, место, факультеты, резервный день) с приглашениями и ответами
кандидатов. Нынешняя группа ЦО (`AssessmentGroup`) становится подгруппой сбора — её видят только
организаторы и эксперты; кандидат видит место и время сбора. Самозапись (места и факультеты у
группы, выбор даты в кабинете) убирается. На оценке ЦО добавляются комментарий к баллу (поле у
`ReviewScore`), комментарии по заданиям ЦО (задания — таблица, правится в админке) и фоновый
комментарий подгруппы; последние два — колонками экспертов с опросом раз в 2 секунды, как
сценарий собеседования.

## Дополнение: автоматическое приглашение поздних анкет

Без миграций и новых зависимостей. `autoInvite` в `lib/assessment/sessions.ts` проверяет
SUBMITTED, текущий сезон, активность пользователя, факультет и отсутствие приглашения;
выбирает через `invitesFaculty` ближайший сбор с `reserve=false`, `invitedAt!=null`,
`startsAt>now`. Использует `readPlace(invited)`, не меняет сбор. `createMany(skipDuplicates)`
защищает уникальность приглашения; только победивший вызов уведомляет.
Общий `notifyInvites` формирует ручное и автоматическое уведомление через `inviteText`,
с прежним ключом и `urgent=true`; `notifyChange` тоже срочный, `remindSession` прежний.
Ошибки `autoInvite` ловятся и логируются, наружу возвращается false.

Отправка анкеты вызывает `autoInvite` после `notifySubmitted`. Подтверждение анкеты
использует нейтральный текст без обещания только будущего приглашения — порядок уведомлений
сохранён, предсказывать результат автоприглашения заранее не требуется.
Ручное приглашение проверяет `placeChanged` до записи и возвращает указанный русский отказ.
Тесты на `sha_test` покрывают выбор, ограничения, гонку, снимок и ночное расписание.
Проверка конституции I–VI: права отправки и аудит сохранены, доставка только `notify`,
подгруппы/оценки и интерфейс кандидата не меняются; коммит и пуш — после зелёного check.

## Дополнение: вместимость слота

Миграция `assessment_session_capacity`: `AssessmentSession.capacity Int @default(50)`.
Никаких переносов или удаления прежних приглашений при миграции.
`lib/assessment/capacity.ts` содержит транзакционный advisory lock на сезон и подсчёт
мест: все собственные приглашения плюс входящие RESERVE для резервного сбора.
Один замок используют `saveSession`, `inviteSession`, `autoInvite`, `answerInvite`.
Так подсчёт свободных мест и запись приглашений/лимита выполняются последовательно.
Уведомления отправляются после завершения транзакции, через прежний `notifyInvites`.

Общий `claimInvites` в `sessions.ts` ограничивает число новых записей свободными местами,
публикует снимок нового слота и сохраняет снимок существующего. Ручной поток заполняет
выбранный и следующие будущие слоты по времени; автоматический — свободные подходящие
слоты после самого раннего сбора факультета с начатой рассылкой. Отдельного нажатия
«Пригласить» по следующему заранее созданному слоту не требуется. Нет места — нет приглашения.

Форма организатора принимает лимит, обзор и страница сбора показывают occupied/capacity.
API приглашения сообщает overflow/unplaced; журнал сохраняет эти числа и изменения лимита.
В резерв нельзя перейти сверх вместимости; выход из резерва освобождает только входящее
резервное место, а исходное приглашение продолжает учитываться.
Проверка конституции I–VI: права/аудит сохранены, распределение не меняет оценки,
уведомления через общий механизм; тесты на отдельной базе включают конкуренцию.
