# Quickstart: проверка фичи

## Подготовка

```bash
npm run db:migrate -- --name assessment_sessions   # при разработке
npm run check
```

Локальное демо: `dev-demo` (порт 3002), база `sha_demo`, «Сбросить демо» пересоздаёт сборы.

## Сценарии

1. **Сбор и приглашение** (US1): как Полина — «Центр оценки» → «Новый сбор» (понедельник,
   СНиМК + МЭО) → «Пригласить на центр оценки». Ожидаем: «Приглашено N»; у кандидатов СНиМК/МЭО
   уведомление, у других — нет; повтор «Пригласить» — «Приглашено 0».
2. **Ответ кандидата** (US2): как кандидат СНиМК — кабинет: плашка ЦО с тремя кнопками →
   «Резервный день». Ожидаем: в кабинете место субботы; у организатора — в «Резервный день».
   Сменить на «Буду» — снова основной сбор.
3. **Счётчики и напоминание** (US3): у сбора 4 счётчика; «Напомнить неответившим» — уведомление
   только молчащим.
4. **Подгруппы и отбивка** (US4): на странице сбора создать 2 подгруппы, назначить экспертов,
   распределить пришедших — блоки с заголовками; ответ `GET /api/cabinet/assessment`
   кандидата не содержит названий подгрупп.
5. **Оценка с комментариями** (US5): как Катя — экран подгруппы: балл + комментарий к нему,
   комментарии к двум заданиям; после обновления — на месте; Илья видит, но не правит.
6. **Фон подгруппы** (US6): Катя пишет фон — у Ильи появляется в течение ~2 с с «пишет…».
7. **Без самозаписи** (US7): в форме подгруппы нет мест и факультетов; в кабинете нет выбора
   даты.
8. **375px**: страницы сбора, подгруппы и кабинета без горизонтальной прокрутки.
