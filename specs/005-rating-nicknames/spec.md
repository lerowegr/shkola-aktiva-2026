# Feature Specification: никнеймы, аватарки, рейтинг

**Feature Branch**: `005-rating-nicknames` (отдельной ветки нет, работа в `main`)

**Created**: 2026-10-06

**Status**: Решения владельца приняты (2026-10-06), к реализации готово

**Решения владельца**:
1. Охват рейтинга — все кандидаты под псевдонимами.
2. Ник уникален (без регистра), смена с паузой 7 дней.
3. Фолбэк — БЕЗ счётчика: нейтральный код вместо «Игрок №N».
4. Аватар — только загрузка, импорта из Telegram нет.

**Input**: в личный кабинет добавить никнейм (без ника — «Username № по
регистрации», принцип могут поменять), аватарку (своя или из Telegram),
рейтинг по никнеймам — по одной игре и общий.

## ⚠️ Конфликт с конституцией (принцип III)

Сейчас: «рейтинг — только своё место и число игроков, без чужих имён».
Публичный рейтинг по никнеймам это правило отменяет. План фиксирует
отступление с обоснованием (так разрешает Governance); поправка в
конституцию — через `/speckit-constitution` вместе с реализацией.

Обоснование: в рейтинге нет персональных данных — только самовыбранный
ник (или обезличенный «Игрок №N») и аватар, загруженный/выбранный самим.
ФИО, почта, факультет наружу не выходят.

## Открытые вопросы

Все четыре решены владельцем (см. шапку). Детализация фолбэка без счётчика:

- `User.seq` всё равно заводим (serial + backfill по `createdAt`) — нужен
  как стабильное зерно, но наружу не показываем.
- Фолбэк: `Игрок ${code(seq)}`, где `code` — 4 символа base32 от
  хэша seq (стабильно, уникально, порядок и число регистраций не читаются).
- Смена принципа позже — тело `displayName()`, без миграций.

## User Scenarios

### US1 — Профиль (P1)

Кандидат открывает «Кабинет → Профиль»: задаёт ник (3–20 символов,
кириллица/латиница/цифры/`_`, регистронезависимо уникален), грузит аватарку
(jpg/png/webp ≤ 5 МБ → webp 256×256) или жмёт «Взять из Telegram»
(только при привязанном TG), видит предпросмотр «как в рейтинге».

Без ника везде показывается `Игрок №N` (N — номер по порядку регистрации).

### US2 — Рейтинг игры (P1)

Под итогом партии и вкладкой в «Мини-играх»: топ-20 игры (место, аватар,
имя, очки) + своя строка с местом из числа игроков. Только кандидаты:
организаторы играют вне рейтинга, как сейчас.

### US3 — Общий рейтинг (P2)

Сумма ранговых баллов: за игру `1000 × (1 − (rank−1)/players)`, не играл — 0.
Топ-20 + своя строка + раскладка баллов по играм. Ежедневное не входит
(серия живёт в профиле отдельно).

## Решения

- `displayName()` — одна чистая функция (`lib/profile/display.ts`): ник или
  `Игрок ${code(seq)}`. Смена принципа фолбэка — в одном месте, без миграций.
- `User.seq` — serial, backfill по `createdAt` (SQL `ROW_NUMBER` в миграции);
  наружу не показываем, только зерно для кода.
- `nicknameNorm` (lower) unique — уникальность без учёта регистра.
- `nicknameChangedAt` — смена не чаще раза в 7 дней.
- Зарезервированные ники (`admin`, `организатор`, …) запрещены кодом.
- Сброс ника staff (право `users.manage`) + `audit` — против самозванцев.
- Аватар: только загрузка. `UPLOADS_DIR/avatars/<uuid>.webp` 256×256 (sharp),
  тип по содержимому, лимит 5 МБ; раздача публичным `/api/avatars/[seq]`
  с вечным кешем; дефолт — инициалы/маскот.
- Общий рейтинг считается на лету из `candidateBests()`; при росте —
  кеш-таблица (не сейчас).
- ФИО/почта в рейтинговые ответы не попадают никогда (отдельный селект).
