# Feature Specification: доп. анимации тетриса + логика пяти игр

**Feature Branch**: `004-games-logic` (отдельной ветки нет, работа в `main`)

**Created**: 2026-10-04

**Status**: Draft

**Input**: владелец пропишет анимации тетриса позже сам; здесь — меню
возможных анимаций с точками вставки и продуманная логика остальных игр
(«Угадай по пикселям», «Змейка», «Викторина», «2048», «Ежедневное задание»).

## Часть 1. Доп. анимации тетриса (на выбор)

Что уже есть как хуки: `tick()` возвращает `{ locked, cleared }`, в
компоненте на них уже висят хаптики; у «Лови» подсмотреть `popups`
(всплывающие очки) и `.shake`. Всё ниже — только CSS + мелкие добавки,
логика падения не меняется. Всё — под
`@media (prefers-reduced-motion: no-preference)`, иначе статично.

| Анимация | Триггер в коде | Что добавить |
|---|---|---|
| Всплывающие очки (+100, +800) | `cleared > 0` в `loop()` | popups как в `Catch.vue` |
| Вспышка сгоревшего ряда | `cleared` + НОВОЕ: `clearedRows: number[]` из `tick()` | белый оверлей на ряды, 250 мс |
| «Тетрис!» (4 ряда): тряска + частицы | `cleared === 4` | `.shake` как в «Лови», ≤30 div-частиц в цветах бренда |
| След жёсткого сброса | `drop()` в компоненте | вспышка колонны + тряска стакана |
| Пульс призрака | всегда (CSS) | opacity-анимация клеток `-1` |
| Бейдж «Уровень N» | вотчер `snap.level` | оверлей 800 мс + пульс счётчика |
| Последние 10 секунд | `left <= 10` | таймер краснеет + пульс |
| Появление фигуры | смена `active` | scale-in клеток фигуры (ключ по счётчику спавнов) |
| Финал (топ-аут/время) | `snap.over` | заливка снизу вверх за 1100 мс до итога |
| Пиксельная сетка фона | всегда (CSS) | линии как в «Лови», едва заметно |

Нужно от модуля (когда дойдёт до реализации): `clearedRows` и, для
pop-анимации фиксации, `lockedCells` в `TickResult`. Рекомендуемый первый
набор: всплывающие очки + вспышка ряда + тряска на тетрисе — их видит
каждая партия.

## Часть 2. Логика игр

Общее для всех: чистый модуль `app/games/*.ts` + тесты, запись в
`lib/games/rules.ts`, значение в Prisma-enum `GameKind` + миграция
(`ADD VALUE` — безопасно), компонент в `<ClientOnly>`, рейтинг только
своё место и число игроков, на отбор не влияет, 375px, хаптики.

### 2.1 «Угадай по пикселям» (PIXEL) — самая простая

- `app/games/pixel.ts`: пул из маскотов (15) и объектов (8) с алиасами
  ответов; `buildParty(rng)` → 5 загадок, у каждой 4 варианта (1 верный +
  3 дистрактора из того же пула).
- Раунд: стадии чёткости 0…4 (блоки 48/24/12/6/исходник), кнопка «Чётче»
  снижает награду. Очки раунда: `[500,400,300,200,100][стадия] +
  max(0, 30 − секунды) × 2`, мимо −50, минимум 0 за раунд.
- Рендер в компоненте: canvas, `imageSmoothingEnabled = false`, два прохода
  (уменьшить → растянуть). `ClientOnly` (тасовка).
- `GAMES`: `better: higher`, `score 0…3000`, `duration 15…300 с`, `moves: null`.

### 2.2 «Змейка в стиле ША» (SNAKE)

- `app/games/snake.ts`: поле 17×17, `step(state, dtMs, rng)` с аккумулятором
  (шаг 140 мс → минимум 90, −2 мс за еду), очередь поворотов (без разворота),
  еда через `rng` мимо тела, стены и себя — смерть.
- Партия 90 с (`SNAKE_SECONDS`) или до смерти. Счёт = съеденное.
- `GAMES`: `score 0…120`, `duration 5…95 с`, `moves: null`.
- Управление: свайп + крестовина + WASD/стрелки. Рендер: DOM-сетка
  (289 клеток, ~7 Гц — как тетрис) или canvas как «Лови» — на выбор
  при реализации. Еда — иконка объекта бренда (один узел с картинкой).

### 2.3 «Викторина о Школе» (QUIZ) — первая с админкой

- БД: `QuizQuestion { seasonId, order, text, options[4], correct 0…3,
  isActive }` + CRUD в `staff/admin` по образцу конструктора анкеты +
  `audit("question.*")` (принцип II).
- `app/games/quiz.ts`: `buildRound(questions, rng)` → 10 вопросов,
  варианты тасуются с пересчётом верного; очки: `100 + секунды_в_запасе × 10`,
  лимит 15 с на вопрос, `ClientOnly`.
- `GAMES`: `score 0…2500`, `duration 30…200 с`, `moves: null`.
- Замечание: ответы уезжают на клиент — уровень защиты как у остальных игр
  (диапазоны). Серверную перепроверку — отдельной задачей, если захочется.

### 2.4 «2048 с маскотами» (MERGE)

- `app/games/merge.ts`: поле 4×4 из плиток `{ id, exp }` (id стабильны ради
  FLIP-анимаций), `move(board, dir, rng)` чистая и тестируемая, спавн
  90% «2» / 10% «4», 11 ступеней (маскоты → логотип-стикер на 2048),
  очки классические (сумма слияний).
- Партия: пока есть ходы, но не дольше 300 с (`MERGE_SECONDS`).
- `GAMES`: `score 0…100 000`, `duration 10…310 с`, `moves: null`.
- Управление: свайп + стрелки. Победа на 2048 — оверлей, партия продолжается.
  Сложность тут в анимациях сдвига/слияния — их отдельно при прописке.

### 2.5 «Ежедневное задание» (DAILY) — самая сложная организационно

- НЕ через `GameKind`: таблица `DailySolution { userId, date, kind, score,
  timeMs }` (уникальность пары человек+день — одна попытка). Таблицы самих
  заданий нет: вид и сид выводятся из даты (`dailyKind`, `seedFromDate`),
  партия — та же форма, что обычная игра, поэтому диапазоны
  правдоподобия общие (`implausible`). День — по Москве
  (`app/utils/moscow.ts`, правило 9).
- Контент v1 — переиспользование с фиксированным сидом от даты (одинаково
  всем, честно): kinds `MEMORY` (расклад из `seeded(дата)`), `PIXEL`
  (фиксированная загадка), `QUIZ` (5 фиксированных вопросов).
- Серия = подряд идущие решённые дни; рейтинг свой (текущая + лучшая серия),
  не `results.ts`. Напоминание — `notify()`, категория SYSTEM, ~10:00 МСК
  нерешившим (ночное правило уже внутри `notify`). Планировщик запуска —
  открытый вопрос плана (server-плагин с интервалом или внешний крон).
- На отбор не влияет (принцип III).

## Порядок внедрения

PIXEL → SNAKE → QUIZ → MERGE → DAILY. Анимации тетриса — в любом момент,
модульные добавки (`clearedRows`, `lockedCells`) — вместе с первой из них.
