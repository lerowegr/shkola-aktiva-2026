# Нагрузочный стенд

Мини-сайт на этом компьютере: выставляете, сколько человек регистрируется
в секунду и как долго, и смотрите, как держится сайт и сервер. Запускаете
вы сами — стенд ничего не делает без кнопки «Старт».

## Что делает одна «регистрация»

Путь кандидата, пришедшего из Telegram: главная → /login → код входа →
знакомство (ФИО, курс, факультет, студбилет, телефон, логин, почта,
пароль — пароль хешируется scrypt, это самое тяжёлое) → кабинет → анкета →
автосохранение ответов (если приём анкет открыт). На локальной копии можно
включить отправку анкеты. Организаторы (до 50) в это время листают «Все анкеты».

Ограничения: до 50 регистраций в секунду, до 10 минут. Автостоп — если за
последние 10 секунд ошибок больше 5% или 95% ответов дольше 3 секунд.

## Порядок

1. Локальная копия — сначала здесь, это безопасно:

   ```bash
   npm run loadtest:local
   ```

   (в отдельном окне; сайт пересобирается сам, если код изменился, — пару минут; `--rebuild` — пересобрать принудительно)

2. Стенд:

   ```bash
   npm run loadtest
   ```

   и открыть http://127.0.0.1:4500

3. На стенде: выбрать цель → «Завести» (кандидатов не меньше, чем
   скорость × длительность; каждый регистрируется один раз) → выставить
   скорость и длительность → «Старт».

4. После теста — «Убрать тестовых людей». На боевом обязательно: иначе
   @loadtest.local останутся в «Людях», дашбордах и рассылках.

## Боевой сайт и демо

- Демо и боевой стоят на одном сервере с другими проектами — нагрузка на
  один задевает остальных. Пробуйте ночью и начинайте с малого (2–5/с).
- Анкеты на боевом и демо тест не отправляет: отправка назначила бы их
  настоящим мастерам.
- До открытия анкеты (17 октября, 12:00) автосохранение ответов не
  проверяется — сайт его не принимает, и тест его пропускает.
- Метрики сервера берутся по SSH ключом `~/.ssh/snimk_vps`.
- Файлы `tokens-*.json` — входы тестовых людей, в git не попадают.
