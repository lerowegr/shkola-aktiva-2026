# Платформа «Школа Актива 2026»

Сайт мероприятия и система отбора: внешний сайт, кабинет кандидата,
кабинет организатора (по образцу «Кабинета мастера отбора»), тех.админка,
дашборды, Telegram-бот, Mini App и PWA. Интерфейс полностью на русском.

- Решения и порядок этапов — `docs/specs/2026-09-28-sha-platform.md`.
- Планы этапов — `docs/plans/`. Сделаны этапы 1 «Каркас», 2 «Анкета и
  кабинет мастера», 3 «Сообщения и уведомления», 4а «Решения и домашнее
  задание», 4б «Собеседования и итоги», 5 «Тех.админка и дашборды»,
  6 «Лендинг», 7 «Мини-игры». Все этапы спецификации пройдены.
- Бренд (палитра, шрифты, опись ассетов) — `docs/brand.md`.
- **Новые фичи — через Spec Kit** (v1.0.13): `/speckit-specify` → `/speckit-plan`
  → `/speckit-tasks` → `/speckit-implement` → `/speckit-converge`; артефакты в
  `specs/NNN-название/`, на русском. Правила, по которым сверяется каждый план, —
  в конституции `.specify/memory/constitution.md` (выжимка раздела ниже). Меняя
  незыблемые правила, правьте оба файла. CLI `specify` нужен только для
  обновления Spec Kit: `uv tool install specify-cli`.
- Ядро входа, сессий, прав и аудита перенесено из `~/СНиМК/portal` —
  там же подсмотреть, если что-то непонятно.

## Стек

Nuxt 4 (Nitro, Vite) · Vue 3.5 · TypeScript · PostgreSQL 16 · Prisma 7 ·
grammY · zod 4 · Tailwind 4 · Vitest. Без Auth.js: сессии свои, в базе.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Приложение на localhost:3000 |
| `npm run check` | Типы + линт + тесты. Прогонять перед каждым коммитом |
| `npm run db:migrate -- --name имя` | Миграция, генерация клиента и накат на тестовую базу `sha_test` |
| `npm run db:seed` | Роли, сезон, этапы, анкета, критерии, маркеры, владелец из `OWNER_EMAIL` (повторять можно) |
| `npm run db:demo` | Демо-кандидаты с отправленными анкетами и второй мастер (`@demo.local`), только не на проде |
| `npm run share` | Сайт по временной ссылке Cloudflare с этого компьютера: сборка, туннель, сервер. Ctrl+C — остановить |
| `npm run user:password -- почта` | Новый случайный пароль человеку (почта или логин), печатается один раз |
| `npm run bot` | Бот (нужен `TELEGRAM_BOT_TOKEN`) |
| пуш в `main` | Автодеплой: проверки → образы на GitHub → сервер (`docs/deploy.md`) |

**Вход — только через Telegram или по паролю** (кода на почту и демо-входов
нет), на /login одна форма для всех (выбора «участник / организатор» нет):
после входа `homeFor()` ведёт организатора в /staff, участника — в /cabinet. Регистрация участника —
только через Telegram; логин, почту и пароль он задаёт при знакомстве
(`checkCredentials`). «Забыли пароль?» — бот (`/start reset`, `/password`)
присылает временный пароль на 24 часа (`lib/auth/temp-password.ts`), после
входа им — обязательная смена (`mustChangePassword`, `/password`).
Организатор задаёт пароль по приглашению; владельцу и в аварийных случаях —
`npm run user:password -- почта` (на сервере — через `dc.sh run --rm migrate`).
Без `TELEGRAM_BOT_TOKEN` и VAPID-ключей доставки в Telegram и пуши
помечаются пропущенными — сайт работает. PWA в разработке выключен;
включить для проверки пушей: `NUXT_PWA_DEV=1 npm run dev`.

## Незыблемые правила

1. **Каждый обработчик, меняющий данные, — через `defineAction` и
   начинается с проверки прав** (`requirePermission` / `requireSignedIn`).
   Маршрут доступен прямым запросом: спрятанная кнопка — не защита.
2. **Права — только через `can()` из `lib/permissions.ts`.** Никаких
   `role === "admin"`: роли собираются в админке, в коде их названий нет.
   Выдать роль можно, только если все её права есть у выдающего
   (`canGrantRole`).
3. **Всё, что организаторы меняют, пишется в аудит** (`audit(event, …)`).
   Оценки решают судьбу кандидатов — спор «кто поставил балл» решается
   записью.
4. **Отбор — единый поток.** Никаких границ направлений/факультетов в
   правах и выборках, пока этого нет в спецификации. Фильтр по факультету
   для просмотра (анкеты, ДЗ, собеседования, ЦО — `lib/profile/faculty.ts`,
   `?faculty=` в адресе) — можно: доступ он не ограничивает.
5. **Состояние этапа вычисляется, а не хранится** — `stageState()` в
   `lib/stages.ts`. Замки вкладок и доступ к этапам — только через него.
   Так же статус оценки: «проверена» = есть балл по каждому критерию
   (`reviewSummary()` в `lib/applications/review.ts`).
6. **Оценку меняет только её мастер** (`lib/applications/review-store.ts`),
   чужие — только чтение. Кандидат никогда не видит баллы, маркеры и
   комментарии: в `lib/applications/candidate.ts` их нет и быть не должно.
   Оценка одна на все этапы (`StageKind`): списки и карточка мастера
   получают этап параметром (`?stage=HOMEWORK`).
7. **Решения видны кандидату только после публикации** этапа целиком
   (`lib/applications/decisions.ts`); опубликованное не меняется.
8. **Файлы кандидатов — не в `public/`**: `UPLOADS_DIR`, отдаёт
   `/api/files/[id]` с проверкой прав. Тип — по содержимому (`%PDF-`).
   Запись на собеседование, перенос и отмена — под замком базы
   (`lib/interviews/booking.ts`).
9. **Всё время — по Москве**: на экране только через `app/utils/moscow.ts`
   (`mskFormat`, `mskTime`, `mskInputValue`/`mskFromInput` для полей дат),
   в SQL — `("поле" AT TIME ZONE 'UTC') AT TIME ZONE 'Europe/Moscow'`.
   Голый `format()` из date-fns и `toLocaleString` без пояса запрещены:
   сервер за рубежом, страница с сервера показала бы UTC.
10. **Интерфейс на русском, включая ошибки.** Сообщение объясняет, что
   случилось и что делать.
11. **Мобильный вид — не потом.** Каждый экран проверяется на 375px.
12. **Уведомления — только через `notify()`** (`lib/notifications/notify.ts`).
   Колокольчик пишется сразу; Telegram и пуш — очередь доставки, их
   разносит `server/plugins/notification-worker.ts` через минуту и только
   если человек не прочитал на сайте; ночью (23–08 МСК) несрочное ждёт утра.
   `notify()` никогда не бросает: уведомление не отменяет действие.
13. **Секреты и одноразовые коды в базе — только хешами** (коды почты,
   токены приглашений). Ответы на вход не раскрывают, есть ли человек в
   системе.
14. **Хостинг за пределами РФ согласован с вузом** — юридическую тему не
   поднимать. Технически: Cloudflare перед сайтом не ставим, перед запуском
   проверяем открываемость с российских мобильных сетей.

## Особенности версий (легко ошибиться по памяти)

- **Nuxt 4**: `~` указывает на `app/`, корень проекта — `~~`.
- **h3 прибит через `overrides` на 1.15.11.** Иначе типы ответов
  обработчиков превращаются в `{}`. Не снимать.
- **Prisma 7**: обязателен `PrismaPg`, строка подключения — в
  `prisma.config.ts`, клиент — в `lib/generated/prisma`. `migrate dev` в 7-й
  версии **не** пересобирает клиент сам — поэтому `npm run db:migrate`
  вызывает `prisma generate`. После изменения схемы dev-сервер держит старый
  клиент («Unknown field») — перезапустить.
- **Типизированные маршруты Nitro**: `$fetch("/api/…")` внутри функции,
  которая возвращает `Promise<ActionResult>`, роняет `vue-tsc` с «Excessive
  stack depth». Указывайте тип явно: `$fetch<ActionResult>(…)`. Для
  `useFetch` с адресом-функцией тип тоже явно: `useFetch<Ответ>(() => …)`.
  Ручка, чей ответ тянет типы из `lib` с базой (таблицы рейтинга), —
  только с локальным интерфейсом на странице (`app/pages/cabinet/rating.vue`):
  импорт типа из `lib` роняет тот же матчер.
- **Компонент, который появляется после загрузки страницы** (выбрали ветку,
  открыли панель), — без `await` в setup: такой асинхронный компонент
  зависает в Suspense и не рисуется. `useFetch` без await и `v-if` на данных.
- **Цифры над вложенным списком** (счётчики, «нераспределённые») — своим
  `await useFetch` в странице. Ни emit из async setup дочернего компонента,
  ни `useNuxtData` чужого ключа не годятся: на сервере страница рисуется
  раньше, чем ребёнок получил данные, — нули и расхождение гидрации.
- **Клиентский код импортирует из `lib/` только чистые модули** (без
  `lib/db`): `form`, `review`, `password-rules`, `permissions`,
  `admin/segments`, `site/content`, `site/landing`, `games/rules`, `games/sha-test`, `assessment/rules`, `profile/onboarding`, `profile/faculty`, `auth/login` и типы (`import type` — можно любые). Значение из модуля,
  который тянет базу, утащит Prisma в браузерную сборку.
- **`$fetch` в setup страницы на сервере идёт без куки посетителя** — и
  получает отказ. Для первой загрузки — `useFetch`; если нужен ручной
  вызов (подгрузка страницами) — `useRequestFetch()`.
- **Лендинг**: three.js и GSAP импортируются только динамически из
  `app/landing/*` — в кабинеты они не попадают, а сервис-воркер не кладёт
  в кеш файлы больше 300 КБ (иначе three.js качал бы каждый). Анимации
  заводятся через `motion()`: при «уменьшить движение» она не вызывается и
  страница стоит. Тексты главной не выдумываем: умолчания в
  `lib/site/content.ts` — только правда о платформе, остальное пишут
  организаторы в «Админка → Сайт»; пустой раздел не показывается.
  Произвольные значения Tailwind с `calc` — с пробелами через `_`
  (`calc((100%_-_72rem)/2)`), иначе CSS молча выкидывает правило.
  На главной системная полоса прокрутки скрыта (`html.landing`), вместо неё
  маскот `LandingScrollbar`; прокрутку саму не подменяем. Перебивка —
  «стикер-бомбинг»: играет по времени при появлении, а не за прокруткой
  (быстрое вращение за прокруткой выглядит рвано). Наклейки с белой
  обводкой — `public/brand/stickers`, готовит `npx tsx scripts/make-stickers.ts`.
  GSAP анимирует внутренний слой: CSS-свойства `translate`/`rotate` он вбирает
  в свой transform и теряет вертикальный сдвиг.
  У Konkovo цифры и заглавные на 0.15em выше заявленной строки: анимируемому
  тексту с `leading-none` — отступ сверху, иначе Safari срезает верх.
- **Фото сайта** (люди, место, история): загрузка `POST /api/admin/site/images`
  (multipart, право `content.manage`), обработка `sharp` в
  `UPLOADS_DIR/site/<key>-480|960|1600|master.webp` без EXIF, раздача
  `/media/site/<id>/<ширина>.webp` с вечным кешем. Тексты ссылаются на фото
  по id (`PhotoRef`); фото без ссылок старше часа убираются при сохранении
  текстов. `sharp` — нативный модуль, он во внешних модулях Nitro.
- **Анкета — по шагам** (`app/components/form/Wizard.vue`): раздел — шаг, шаг —
  в адресе `?step=`. Разделы — таблица `FormSection` (название, описание,
  порядок), вопросы ссылаются на раздел по названию; сквозной `order` вопросов
  всегда идёт по разделам (`renumberQuestions`), поэтому всё, что сортирует по
  `order`, показывает по шагам. Форматы строки (`formatValue`: цифры, группа,
  телефон, ВК → vk.ru, Telegram) и минимум знаков — в чистом
  `lib/applications/form.ts`, одни правила для «Далее» и отправки.
- **Домашнее задание — раздел анкеты** (`FormSection.homework`): задания —
  вопросы-ссылки этого раздела, текст задания в подсказке (`FormRichHelp`:
  блок `[чат]…[/чат]` рисуется перепиской). При отправке анкеты ответы раздела
  становятся сдачей ДЗ (`Submission` HOMEWORK, `homeworkText`) — по ней работа
  в «Оценке ДЗ», решениях и рассылках; мастер ДЗ назначается тогда же.
  Файлов ДЗ нет: ни сайт, ни бот их не принимают. Кандидату отдельным этапом
  ДЗ не показываем. Портрет участника (критерии, маркеры, вопросы, задания) —
  `lib/applications/portrait.ts` из таблиц организаторов; на сайт его
  переносит `scripts/apply-portrait.ts`, пока нет оценок и ответов.
- **Отсева между этапами нет**: каждый, кто отправил анкету, проходит ДЗ, ЦО и
  собеседование (запись — `allowed` в `lib/interviews/booking.ts`, ЦО —
  `lib/assessment/candidate.ts`). Решение одно — «Итоги отбора» (`/staff/decisions`,
  `rankFinal` — сумма средних баллов этапов), хранится как решение этапа
  INTERVIEW (`FINAL_STAGE`). Промежуточных «не прошёл» кандидат не получает.
  Лента этапов в кабинете — с личным статусом (`personal` у `AppStageTimeline`).
  Минимум знаков в анкете — совет, не запрет; для ссылки на ДЗ советуем Google Диск.
- **Демо-копия** (`NUXT_PUBLIC_DEMO=true`, demo.schoolofactivity.ru, своя база):
  вход «как…» и сброс — `server/api/demo/*` под `requireDemo` (на боевом 404),
  сценарий отбора — `lib/demo/scenario.ts` (люди @demo.local). Новый экран или
  этап — подумать, кем из демо-людей его показать.
- **Знакомство** (`/cabinet/welcome`): кандидат без `User.onboardedAt` в кабинет не
  попадает (`needsProfile` в сессии, `auth.global.ts`), а анкету, ДЗ и
  запись сервер не принимает (`requireProfile`). Поля — ФИО, курс 1/2, факультет,
  студбилет, телефон (`lib/profile/onboarding.ts`, чистый). В анкету подставляются по смыслу (`suggestAnswers`):
  показ — в `loadCandidateApplication`, запись — при отправке. Mini App
  (`/tg`, бот @FU_SHA_2026_bot) сначала предлагает тест или сайт.
  Кнопки бота используют `?screen=test|site`, уведомления — прямой `?to=`.
  Тест (`/test`) доступен после входа без знакомства; под результатом — регистрация
  или кабинет. При выборе сайта новичок (`needsProfile`) видит главную,
  зарегистрированный — кабинет, организатор — кабинет организатора.
- **«Тест про ША»** (`GameKind` QUIZ, `/cabinet/games/quiz`) — перенесённый Mini
  App «ША бот внешка»: все активные `QuizQuestion` по порядку, попытка одна
  (`QuizAttempt`, уникально на человека и на Telegram), счёт считает сервер
  (`lib/games/sha-test.ts`), верные ответы в браузер не уходят — поэтому
  ручки с вопросами викторины для кандидата нет, а «Викторина» задания дня
  берёт только встроенный пул `app/games/quiz.ts`. В рейтинг не идёт
  (`RATED_GAMES`). Результаты бота перенесены `scripts/import-bot-test.ts`
  с `source=BOT` и находятся по Telegram при входе. Итоги и CSV —
  «Админка → Тест про ША».
- **Мини-игры** на отбор не влияют: результаты не попадают в карточки
  оценки. Рейтинг публичен под псевдонимами (`lib/profile/display.ts`):
  ник или обезличенный код, настоящих имён нет; место и число игроков —
  как раньше, только своё — в итогах партии. Организаторы видят
  соответствия в админке.
  Игры со случайностью рисуются в `<ClientOnly>`: иначе сервер и браузер
  перемешают по-разному и разметка разойдётся.
- **Центр оценки** (этап `ASSESSMENT`, между ДЗ и собеседованием) — очный
  групповой. Группа: корпус, аудитория, время, эксперты, кандидаты (одна группа
  на кандидата). Оценка — обычная `Review` этапа ASSESSMENT на пару «эксперт
  группы × кандидат группы»; заготовки создаются при назначении, пустые
  убираются при переносе, начатые остаются. Кандидат видит описание этапа и
  снимок места из последней рассылки (`notified`), правка без рассылки ему не
  видна — организатору горит «сообщите снова». Результатов ЦО кандидат не видит
  вовсе, допуск к собеседованию от ЦО не зависит.
  **Самозапись**: у группы `capacity` (мест) и `faculties` (пусто — всем). Такую
  дату кандидат выбирает сам на `/cabinet/assessment` — только свой факультет
  (из знакомства), есть места, не позже чем за 2 ч; перенос и отмена — за 12 ч
  (`lib/assessment/candidate.ts`, правила — `rules.ts`, под замком базы). Место
  он видит сразу, без рассылки. Уведомление «Анкета отправлена» зовёт выбрать
  дату, если она уже есть. «Разложить поровну» — только по группам без мест.
  Сид идёт на каждом выкате (`deploy/apply.sh`) и только досоздаёт недостающее —
  так новые этапы и их стартовые критерии доезжают до прода.
- **Графики дашборда** — свои SVG (`app/components/dash`) по правилам
  скилла dataviz: одна ось, тонкие столбики со скруглённым концом, легенда
  при двух рядах, подсказка на наведении и с клавиатуры, таблица под
  графиком. Цвета рядов — `--color-brand-blue` и `--color-brand-orange`
  (проверены на различимость); текст — только цветами текста.
- **Tailwind 4**: настройка в CSS через `@theme static` (`app/assets/css/main.css`),
  конфига нет. Там палитра и шрифты брендбука — описание в `docs/brand.md`.
  `static` обязателен: без него переменные, не встреченные в классах, не
  попадают в CSS, и `var(--color-brand-…)` из стилей или 3D-кода пустой.
- **Telegram**: параметр `/start` — не длиннее 64 знаков, `callback_data` —
  64 байт. Поэтому код входа — 32 знака base64url.
- **Кука сессии** `sha_session` / `__Secure-sha_session`, на https —
  `SameSite=None` (иначе не доезжает в Mini App на компьютере); защиту от
  чужих сайтов держит `server/middleware/origin.ts`.
- `nuxt typecheck` печатает предупреждение про `vue-router/volar` — это не
  ошибка, код выхода 0. Бот, скрипты и сид Nuxt не проверяет —
  `npm run typecheck` дополнительно гоняет `tsc -p tsconfig.scripts.json`.

## Сервер

Общий сервер с двумя десятками чужих проектов: свои там только
`/root/sha-site`, контейнеры и тома `sha-site*`, порт `127.0.0.1:3110`.
Собирать на сервере нельзя (мало памяти) — образы собирает GitHub Actions.
Порты 80/443 держит общий edge-nginx (`/root/infra`), чужие сервисы
(в том числе туннель `cloudflared-sha` квиза) не трогать. Всё про деплой,
откат и домен — `docs/deploy.md`.
