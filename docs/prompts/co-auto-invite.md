# Задача: автоприглашение на центр оценки сразу после отправки анкеты + срочная доставка

Проект: `/Users/egor/ША сайт + отбор` (Nuxt 4, Prisma 7, PostgreSQL, zod 4, Vitest).
**Сначала прочитай `CLAUDE.md` и `AGENTS.md`** — там правила проекта и ловушки
версий. Интерфейс и все сообщения — на русском. Время — по Москве. Пуш в `main`
автоматически выкатывает на прод, поэтому **не пушь, пока не пройдёт `npm run check`**.

## Контекст

Центр оценки (ЦО) уже сделан (spec `specs/012-assessment-invitations/`):

- `AssessmentSession` — сбор: место, время, факультеты (`faculties`), флаг `reserve`
  (один резервный на сезон), `invited` — снимок места на момент приглашения,
  `invitedAt`.
- `AssessmentInvite` — одно на анкету (`applicationId @unique`): `sessionId`,
  `answer` (GOING / RESERVE / CANT / null).
- `lib/assessment/sessions.ts` → `inviteSession(seasonId, sessionId, applicationIds?)`
  создаёт приглашения и шлёт `notify(...)` с ключом `assessment-invite:{inviteId}`.
  Организатор жмёт «Пригласить на центр оценки».
- Чистые правила — в `lib/assessment/rules.ts` (`invitesFaculty`, `placeOf`,
  `readPlace`, `placeChanged`, `placeProblem`).
- Отправка анкеты: `server/api/cabinet/application/submit.post.ts`, в конце вызывает
  `notifySubmitted(application.id, user.id)` из `lib/applications/notifications.ts`
  (текст «Анкета отправлена… Приглашение на центр оценки пришлём здесь.»).
- `notify(inputs, { urgent })` в `lib/notifications/notify.ts`. Колокольчик на
  сайте появляется сразу. Telegram и пуш уходят через минуту, если на сайте не
  прочитано. Ночью (23–08 МСК) несрочное ждёт утра; `urgent: true` — не ждёт.
  `notify()` никогда не бросает исключение.

Проблема: анкету ещё принимают. Тот, кто отправит её после того, как организатор
нажал «Пригласить», приглашения не получит, пока организатор не нажмёт ещё раз.
Ночью приглашение в Telegram приходит только в 8 утра.

## Что сделать

### 1. Срочная доставка приглашений
В `lib/assessment/sessions.ts` передавать `{ urgent: true }` в `notify` для
приглашения (`inviteSession`) и для «Сообщить об изменении» (`notifyChange`).
Напоминание (`remindSession`) оставить несрочным: ночью будить незачем.

### 2. Автоприглашение при отправке анкеты
Новая функция в `lib/assessment/sessions.ts`, например
`autoInvite(applicationId): Promise<boolean>`:

- Анкета в статусе `SUBMITTED` и текущего сезона, у пользователя есть `faculty`,
  приглашения ещё нет. Иначе ничего не делать и вернуть `false`.
- Подходящий сбор: не резервный (`reserve: false`), его факультеты включают
  факультет кандидата (`invitesFaculty`), **организатор уже приглашал на него**
  (`invitedAt != null`, то есть рассылка по сбору стартовала) и сбор ещё не начался
  (`startsAt > now`). Если таких несколько, взять ближайший по `startsAt`.
- Место для кандидата — **снимок `invited` сбора** (`readPlace(session.invited)`),
  а не текущие поля. Если организатор поменял место и ещё не нажал «Сообщить об
  изменении», новый кандидат должен видеть то же, что остальные.
  **`invited` и `invitedAt` сбора при автоприглашении не трогать.**
- Создать `AssessmentInvite` с учётом гонки: `applicationId` уникален, используй
  `createMany({ skipDuplicates: true })` или ловушку уникальности. Отправить то же
  уведомление, что и `inviteSession`: тот же текст через `inviteText`, тот же ключ
  `assessment-invite:{inviteId}`, `url: "/cabinet/assessment"`, `urgent: true`.
  Общий код вынести в функцию, а не копировать.
- Никогда не бросать: ошибка автоприглашения не должна ломать отправку анкеты.
  Оберни вызов в try/catch и залогируй ошибку.
- Вызывать в `submit.post.ts` после `notifySubmitted`. Если приглашение ушло,
  текст «Анкета отправлена» лучше не противоречить ему. Самое простое:
  `notifySubmitted` принимает флаг и при автоприглашении пишет «…Приглашение на
  центр оценки — в следующем уведомлении» вместо «пришлём здесь».

### 3. Защита снимка при ручном повторном «Пригласить»
Сейчас `inviteSession` при каждом вызове перезаписывает `session.invited`
текущим местом. Если место поменяли, а «Сообщить об изменении» не нажали,
повторное приглашение молча меняет снимок: старые приглашённые увидят новое место
без уведомления, а предупреждение «место изменилось» пропадёт. Исправить: если у
сбора уже есть снимок и `placeChanged(readPlace(session.invited), placeOf(session))`,
то возвращать `{ ok: false, message: "Место или время сбора изменились после
приглашения — сначала нажмите «Сообщить об изменении», потом приглашайте новых." }`.

### 4. Тесты (`lib/assessment/sessions.test.ts`, образец — существующие тесты там)
- Автоприглашение: кандидат подходящего факультета после старта рассылки
  приглашается в ближайший будущий сбор и получает одно уведомление.
- До первого «Пригласить» по сбору (`invitedAt = null`) автоприглашения нет.
- Без факультета, с чужим факультетом, если сбор уже начался, если приглашение
  уже есть — `false`, приглашение не создаётся.
- Снимок места не меняется автоприглашением, новый кандидат видит место из снимка.
- Повторный ручной `inviteSession` после смены места без «сообщить» — отказ.

### 5. Проверка
- `npm run check` (типы + линт + тесты) — зелёный.
- Если меняешь схему (не должно понадобиться) — `npm run db:migrate -- --name …`.
- Поправь раздел «Центр оценки» в `CLAUDE.md` одной-двумя фразами: автоприглашение
  при отправке анкеты, приглашения срочные.
- Коммит на русском, коротким заголовком. Пушить в `main` только после зелёного
  `check`.

## Чего не делать
- Не трогать подгруппы, оценки, комментарии, кабинет кандидата (кроме текста
  `notifySubmitted`).
- Не приглашать в резервный сбор автоматически: туда попадают только ответом
  «резервный день» или вручную.
- Не обходить `notify()` и не слать в Telegram напрямую.
