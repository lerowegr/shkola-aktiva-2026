# Этап 4а «Решения и домашнее задание» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Главный организатор решает, кто проходит с анкеты на домашнее задание, и публикует результаты; прошедшие сдают ДЗ файлом на сайте или боту; мастера оценивают ДЗ во вкладке «Центр оценки» той же оценкой по критериям.

**Architecture:** Оценка уже обобщена по `StageKind` — списки и карточка мастера получают вид этапа параметром. Решение по этапу — отдельная запись `StageDecision` (прошёл / не прошёл) с черновиком и публикацией: пока не опубликовано, кандидат ничего не видит. Файлы — на диске в `UPLOADS_DIR`, раздаются только через обработчик с проверкой прав (это личные работы). ДЗ мастеру назначается тому же, кто проверял анкету, если он ещё мастер, иначе — по нагрузке.

**Spec:** `docs/specs/2026-09-28-sha-platform.md`

## Global Constraints

- Всё из `CLAUDE.md`.
- Решения видит кандидат только после публикации; публикация — одним действием для всего этапа, с уведомлением каждому.
- Файл ДЗ: PDF, до 20 МБ. Хранится вне `public/`; отдаётся владельцу и организаторам с правом смотреть анкеты.
- Сдать ДЗ может только прошедший этап анкеты, пока этап ДЗ открыт; пересдать — до дедлайна (новая версия заменяет старую, старая остаётся в истории).

## Задачи

### Task 1: Схема
- [x] `Stage.description` — текст задания (для ДЗ) или пояснение этапа.
- [x] `DecisionOutcome { PASSED REJECTED }`; `StageDecision` (applicationId, stageKind, outcome, decidedById, decidedAt, publishedAt; `@@unique([applicationId, stageKind])`).
- [x] `Upload` (userId, filename, mime, size, storageKey, createdAt).
- [x] `Submission` (applicationId, stageKind, uploadId?, text?, submittedAt, replacedAt?) — история сдач; актуальная — последняя без `replacedAt`.
- [x] Сид: критерии ДЗ («Качество выполнения» 0–4, «Креативность» 0–2, «Соблюдение дедлайна» 0–2) и маркеры («Оформление», «Самостоятельность»).

### Task 2: Обобщить оценку по этапу
- [x] `lib/applications/staff.ts`, `review-store.ts`, `assign.ts`, обработчики и страницы мастера принимают `stage` (APPLICATION | HOMEWORK | INTERVIEW).
- [x] В список этапа попадают только допущенные к нему: для HOMEWORK — с опубликованным PASSED по APPLICATION и сданной работой.
- Тесты: список ДЗ не показывает непрошедших и не сдавших; оценка ДЗ не смешивается с оценкой анкеты.

### Task 3: Решения — `lib/applications/decisions.ts`
**Produces:** `setDecision(applicationId, stage, outcome | null, actorId)`, `rankForStage(seasonId, stage)` (итог, среднее по мастерам, статус проверки, решение), `publishDecisions(seasonId, stage, actorId) → { passed, rejected }` (уведомляет каждого; повторная публикация уведомляет только новых), `candidateProgress(userId)`.
- Тесты: решение без публикации кандидату не видно; публикация ставит publishedAt и шлёт уведомления; опубликованное решение менять нельзя — кандидат уже получил результат; повторная публикация касается только новых решений.

### Task 4: Файлы
- [x] `lib/uploads.ts`: сохранить поток в `UPLOADS_DIR` под случайным ключом, проверить сигнатуру PDF (`%PDF-`), размер; удалить.
- [x] `GET /api/files/[id]` — отдаёт владельцу и организаторам с `applications.review`/`view_all`, `Content-Disposition` с исходным именем, `X-Content-Type-Options: nosniff`.
- Тесты: не-PDF с расширением .pdf отклоняется; чужому кандидату файл не отдаётся.

### Task 5: Домашнее задание у кандидата
- [x] Кабинет: карточка этапа ДЗ — «откроется», «текст задания + дедлайн + загрузка», «сдано {дата} — можно пересдать до дедлайна», «не прошли этап анкеты».
- [x] `POST /api/cabinet/homework` (multipart: файл и/или комментарий) → `Submission`, назначение мастеру, уведомления.
- [x] Бот: PDF в личку, когда этап ДЗ открыт и человек допущен, — это сдача ДЗ; иначе понятный ответ.

### Task 6: «Центр оценки» и решения у организаторов
- [x] Вкладка «Центр оценки» открывается вместе с этапом ДЗ: списки «мои / все» по HOMEWORK, карточка — слева задание и сданная работа (файл, комментарий, история версий), справа оценка.
- [x] `/staff/decisions?stage=APPLICATION|HOMEWORK` (право `applications.decide`): рейтинг по итогу, отметки «проходит / не проходит», порог «отметить всех от N баллов», счётчики, «Опубликовать результаты» с подтверждением.
