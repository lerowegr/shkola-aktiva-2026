# Этап 4б «Собеседования и итоги» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Организаторы нарезают слоты собеседований и назначают собеседующих; прошедшие ДЗ сами записываются на свободное время, могут перенести или отменить запись; накануне и за час приходят напоминания; собеседующие оценивают по критериям; итоги этапа публикуются через «Решения» — кандидат видит «Вы в Школе Актива!».

**Architecture:** Слот — время, место и собеседующие; запись — связь слота и анкеты. При записи каждому собеседующему создаётся оценка этапа INTERVIEW — и собеседование появляется у него в списке, а карточка оценки та же, что у анкет и ДЗ. Вместимость и «одна активная запись на анкету» держатся под замком базы. Напоминания досоздаёт разносчик раз в минуту, ключи событий не дают задвоить.

**Spec:** `docs/specs/2026-09-28-sha-platform.md`

## Global Constraints

- Всё из `CLAUDE.md`.
- Записаться может только прошедший ДЗ (решение опубликовано), пока этап собеседований открыт; не позже чем за 2 часа до начала.
- Перенести или отменить запись — не позже чем за 12 часов до начала.
- Нарезать и удалять слоты — право `interviews.manage`; удалить можно только слот без записей.

## Задачи

### Task 1: Схема и сид
- [x] `InterviewSlot` (seasonId, startsAt, endsAt, location, capacity, createdById), `SlotInterviewer` (slotId, userId), `InterviewBooking` (slotId, applicationId, createdAt, cancelledAt).
- [x] Сид: критерии собеседования («Коммуникация», «Мотивация», «Командность» — 0–4) и маркеры («Сильные стороны», «Что насторожило», «Куда направить»).

### Task 2: Логика — `lib/interviews/{slots,booking,reminders}.ts`
**Produces:** `cutSlots({ date, from, to, duration, gap, capacity, interviewerIds, location })` (чистая нарезка), `createSlots`, `deleteSlot`, `availableSlots(seasonId, now)`, `book(userId, slotId, now)`, `cancel(userId, now)`, `dueReminders(bookings, now)` (чистая), `materializeReminders(now)`.
Тесты: нарезка 10:00–12:00 по 20 минут с перерывом 10 → 4 слота; занятый слот (вместимость 1) второму не даётся, даже одновременно; одна активная запись — новая запись переносит; перенос/отмена меньше чем за 12 ч — отказ; без прохода ДЗ — отказ; при записи у собеседующих появляются оценки, при переносе к другим — пустые оценки старых удаляются; напоминания за сутки и за час — по одному разу.

### Task 3: Организаторы — вкладка «Собеседования»
- [x] Расписание по дням: слоты с временем, местом, собеседующими и записанным кандидатом (ссылка на карточку оценки `?stage=INTERVIEW`); фильтр «Мои».
- [x] Нарезка слотов (право `interviews.manage`): дата, с/по, длительность, перерыв, вместимость, место, собеседующие; удаление пустого слота.
- [x] Карточка оценки собеседования: слева время и место, работа ДЗ и анкета; справа оценка.

### Task 4: Кандидат
- [x] `/cabinet/interview`: свободные слоты по дням → «Записаться»; текущая запись с «Перенести» и «Отменить» (по правилу 12 часов).
- [x] Карточки в кабинете: «Вы прошли на собеседование — выберите время», «Вы записаны на …», итог отбора после публикации решений по собеседованию.

### Итоговая проверка
- [x] `npm run check` зелёный.
- [x] В браузере: нарезка слотов → решения ДЗ опубликованы → кандидат записывается → собеседующий видит запись и оценивает → решения по собеседованию → кандидат видит итог.
