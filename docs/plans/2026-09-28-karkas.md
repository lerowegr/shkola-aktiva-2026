# Этап 1 «Каркас» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Рабочий скелет платформы ША: Nuxt-приложение с базой, входом кандидатов (Telegram, почта) и организаторов (Telegram, пароль по приглашению), правами, журналом действий, сезоном и этапами с «замками».

**Architecture:** Один Nuxt 4 проект: страницы в `app/`, HTTP-обработчики в `server/`, чистое ядро без Vue и Nitro в `lib/` (его и тестируем). Ядро входа, сессий, прав и аудита переносится из `~/СНиМК/portal` с упрощениями: без Auth.js (сессии свои), без направлений (единый поток). Бот — отдельный процесс `bot/main.ts` на grammY в том же репозитории.

**Tech Stack:** Nuxt 4.5, Vue 3.5, TypeScript, Prisma 7 (драйвер-адаптер `PrismaPg`), PostgreSQL 16, zod 4, grammY, nodemailer 9, Tailwind 4, Vitest 4.

**Spec:** `docs/specs/2026-09-28-sha-platform.md`

## Global Constraints

- Интерфейс и все сообщения об ошибках — на русском, человеческим языком.
- Каждый обработчик, меняющий данные, — через `defineAction` и начинается с проверки прав (`requirePermission` / `requireSignedIn`).
- Права проверяются только через `can()` из `lib/permissions.ts`; никаких `role === 'admin'` в коде.
- Всё, что меняет данные организаторами, пишется в `AuditLog`.
- Nuxt 4: `~` — это `app/`, корень проекта — `~~`. `h3` прибит через `overrides` на `1.15.11`.
- Prisma 7: клиент генерируется в `lib/generated/prisma`, подключение — в `prisma.config.ts`, в коде только через `PrismaPg`.
- Tailwind 4: настройка в CSS через `@theme`, без `tailwind.config.js`.
- Мобильный вид с первого экрана: 375px без горизонтальной прокрутки.
- Тесты — на отдельной базе `sha_test`, файлы не параллелятся.
- Коммиты — только по просьбе пользователя.

### Task 6: Вход по почте для кандидатов

**Files:** Create `lib/auth/email-code.ts` (+ тест), `lib/mail.ts`, `server/api/auth/email-{request,verify}.post.ts`.

**Produces:** `requestEmailCode(email) → { ok: true } | { ok: false; reason: "too_often" }`, `verifyEmailCode(email, code) → { ok: true; userId } | { ok: false; reason: "wrong" | "expired" | "too_many" }`, `sendMail({ to, subject, text })`.

Правила: код 6 цифр, живёт 10 минут, 5 попыток на код, не чаще одного письма в минуту на адрес, в базе — `sha256(AUTH_SECRET + email + code)`. Верный код создаёт кандидата, если адрес новый, и ставит `emailVerifiedAt`. Без SMTP письмо печатается в консоль сервера.

- [x] Тесты: верный код впускает и гасится; неверный увеличивает `attempts`; шестая попытка — `too_many` даже с верным кодом; просроченный — `expired`; второй запрос раньше минуты — `too_often`; новый адрес создаёт пользователя ровно один раз.

### Task 8: Сезон и этапы

**Files:** Create `lib/stages.ts` (+ тест), `prisma/seed.ts`, `server/api/season.get.ts`.

**Produces:** `stageState(stage: { mode; opensAt; closesAt }, now) → "upcoming" | "open" | "closed"`, `currentSeason() → Season & { stages: (Stage & { state })[] }`.

Правило: `mode = OPEN|CLOSED` — ручное решение, побеждает даты; `AUTO` — по датам: до `opensAt` — `upcoming`, с `opensAt` до `closesAt` — `open`, после — `closed`; без `opensAt` — `upcoming`; без `closesAt` после открытия — `open`.

- [x] Тесты на каждую ветку правила и на границы (ровно в `opensAt` — открыт, ровно в `closesAt` — закрыт).
