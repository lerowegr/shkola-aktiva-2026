# Этап 5 «Тех.админка и дашборды» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Всё, что сейчас правится только сидом и базой, — правится в интерфейсе: роли и их права, люди и их роли, вопросы анкеты, критерии и маркеры этапов. Плюс рассылки по сегментам, журнал действий и дашборды по всему отбору.

**Architecture:** Раздел «Админка» в кабинете организатора (`/staff/admin/*`), каждая страница закрыта своим правом. Правки, которые могут сломать уже собранные данные (удалить вопрос с ответами, критерий с баллами, урезать шкалу ниже поставленных баллов), запрещены с объяснением — логика в `lib/admin/*` и покрыта тестами. Дашборды считаются SQL-агрегатами в `lib/dashboards.ts`, графики — свои лёгкие SVG-компоненты по правилам скилла dataviz, без тяжёлых библиотек.

**Spec:** `docs/specs/2026-09-28-sha-platform.md`

## Global Constraints

- Всё из `CLAUDE.md`.
- Роль можно создать, изменить или выдать, только если все её права есть у самого человека (`canGrantRole`); системные роли не удаляются; владельца нельзя заблокировать, себя — тоже.
- Тексты сайта (контент лендинга) — на этапе лендинга, вместе с самим лендингом: структура контента рождается из дизайна.

## Задачи

### Task 1: Роли — `lib/admin/roles.ts`, `/staff/admin/roles`
- [x] Список ролей с числом людей; создание и правка: название, описание, цвет, права галочками по группам; удаление несистемной роли без людей.
- Тесты: нельзя выдать роли право, которого нет у правящего; неизвестные права выкидываются; системную не удалить; роль с людьми не удалить.

### Task 2: Люди — `lib/admin/people.ts`, `/staff/admin/people` (бывшая «Команда»)
- [x] Поиск по всем людям (организаторы и кандидаты); у человека — роли (выдать / снять с проверкой `canGrantRole`), блокировка / разблокировка, новая ссылка-приглашение.
- Тесты: блокировка владельца и самого себя запрещена; блокировка обрывает сессии; снять роль, права которой у тебя нет, нельзя.

### Task 3: Анкета и оценка — `lib/admin/forms.ts`, `/staff/admin/forms`
- [x] Вопросы анкеты: добавить, править текст/подсказку/обязательность/варианты, переставить, удалить (только без ответов).
- [x] Критерии и маркеры по этапам: добавить, править название, пометку, шкалу и расшифровки, удалить (только без баллов/заметок); шкалу нельзя сделать меньше уже поставленного балла.
- Тесты на каждое «нельзя».

### Task 4: Рассылки — `lib/admin/broadcast.ts`, `/staff/admin/broadcast`
- [x] Сегменты: все кандидаты; начали анкету, но не отправили; отправили анкету; прошли этап X; не прошли этап X; сдали ДЗ; записаны на собеседование; организаторы. Предпросмотр — сколько человек; отправка — уведомление категории «Важное» во все каналы, в журнал.
- Тесты: сегменты считают правильных людей; заблокированные не попадают.

### Task 5: Журнал — `/staff/admin/audit`
- [x] Лента действий с фильтром по виду и человеку, человеческие подписи действий (`lib/audit-labels.ts`), подгрузка страницами.
