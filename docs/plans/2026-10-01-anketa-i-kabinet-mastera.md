# Этап 2 «Анкета и кабинет мастера» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Кандидат заполняет анкету с автосохранением и отправляет её; анкета сама уходит наименее загруженному мастеру; мастер проверяет её по критериям с расшифровкой баллов, пишет маркеры и комментарий — всё сохраняется само, как в «Кабинете мастера отбора».

**Architecture:** Анкета и оценка устроены обобщённо — по виду этапа (`StageKind`): вопросы, критерии и маркеры привязаны к сезону и этапу, поэтому на этапе 4 домашнее задание и собеседование переиспользуют ту же оценку. Чистая логика (проверка ответов, итог и статус оценки, выбор мастера) — в `lib/applications/` и покрыта тестами; обработчики — тонкие. Вопросы, критерии и маркеры по умолчанию кладёт сид; редактор — на этапе 5.

**Tech Stack:** как в этапе 1.

**Spec:** `docs/specs/2026-09-28-sha-platform.md`; образец интерфейса — PDF «Инструкция для мастеров отбора» (кабинет sst-otbor-2026).

## Global Constraints

- Всё из `CLAUDE.md` («Незыблемые правила»).
- Оценку меняет только тот, кому она назначена; чужие — только чтение.
- Кандидат никогда не видит баллы, маркеры и комментарии.
- Каждое изменение оценки пишется в аудит; текстовые правки — не чаще раза в 5 минут на поле.
- Отправить анкету можно только пока этап «Анкета» открыт (`stageState`).

## Модель данных

- `QuestionType { SHORT_TEXT LONG_TEXT SINGLE_CHOICE MULTI_CHOICE URL }`
- `FormQuestion` — seasonId, stageKind, order, section, type, label, help, required, options `String[]`, maxLength.
- `ApplicationStatus { DRAFT SUBMITTED }`
- `Application` — seasonId, userId (`@@unique([seasonId, userId])`), status, lastName, firstName, middleName, studentId, submittedAt.
- `Answer` — applicationId, questionId, value `Json` (строка или массив строк), `@@unique([applicationId, questionId])`.
- `Criterion` — seasonId, stageKind, order, title, badge (например «Сквозная»), maxScore, levels `Json` (`{ score, text }[]`).
- `Marker` — seasonId, stageKind, order, title, example.
- `Review` — applicationId, stageKind, reviewerId, comment, updatedAt, updatedById, assignedById; `@@unique([applicationId, stageKind, reviewerId])`.
- `ReviewScore` — reviewId, criterionId, score; `@@unique([reviewId, criterionId])`.
- `ReviewMarker` — reviewId, markerId, note; `@@unique([reviewId, markerId])`.

Вопросы (раздел — вопрос — тип):
- О себе: курс (выбор), учебная группа, форма обучения (выбор), ссылка на ВК (адрес), откуда узнал(а) о ША (выбор).

### Task 2: Логика анкеты — `lib/applications/form.ts`
**Produces:** `normalizeAnswer(question, raw) → { ok: true, value } | { ok: false, message }`, `missingRequired(questions, answers, profile) → string[]` (подписи незаполненных).
Тесты: пустая строка у необязательного — ок и сохраняется как пусто; выбор вне вариантов — отказ; мультивыбор чистит дубли; адрес без схемы получает `https://`, мусор — отказ; превышение maxLength — отказ; `missingRequired` видит пустые ФИО и студбилет и пустые обязательные ответы.

### Task 3: Логика оценки — `lib/applications/review.ts`
**Produces:** `reviewSummary(criteria, scores) → { total, max, status: "new" | "progress" | "done" }`, `validScore(criterion, score)`.
Тесты: ни одного балла — new; часть — progress; все — done; итог и максимум — суммы; балл вне 0…max — невалиден.

### Task 4: Распределение — `lib/applications/assign.ts`
**Produces:** `pickReviewer(loads: { id, load }[]) → id | null` (меньше нагрузка → раньше; при равенстве — стабильно по id), `reviewerPool(seasonId)` (все активные с `applications.review`, кроме заблокированных), `assignApplication(applicationId, stageKind, assignedById)` — создаёт Review наименее загруженному, если назначения ещё нет.
Тесты: pickReviewer — пустой пул → null; наименьшая нагрузка; равенство → детерминированно. assignApplication на базе — две анкеты на двух мастеров расходятся по одной; повторный вызов не создаёт второе назначение; без мастеров — анкета остаётся нераспределённой.

### Task 5: Кабинет кандидата

- [x] `POST /api/cabinet/application/answer` — сохранить один ответ (только черновик и открытый этап).
- [x] `POST /api/cabinet/application/profile` — ФИО и студбилет.
- [x] `POST /api/cabinet/application/submit` — проверка `missingRequired`, статус SUBMITTED, `assignApplication`, аудит.
- [x] `/cabinet` — карточка анкеты: «Заполнить», «Черновик, N из M», «Отправлена {дата}», «Откроется {дата}», «Приём закрыт».
